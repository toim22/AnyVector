# Vector — Architecture

Vector is a Windows vector-graphics editor written in Rust. From version 0.1.0 the interface follows the
CorelDRAW 2026 reference in `C:\Users\anton\Documents\Claude\corel-screenshots\MAPEAMENTO` (screenshots of every
menu, dialog, docker, tool and toolbar, plus the inventory and the functional notes). `docs/PLAN-0.1.0.md` has the
plan and the decisions; `docs/COVERAGE.md` tracks every item of the reference.

## Workspace

| Crate | Role |
|---|---|
| `vector-core` | Document model: pages, layers, objects (rectangles, ellipses, polygons, spirals, curves, text, images, groups, PowerClips, tables, dimensions, connectors, blends, symbols), styles, effects, geometry (booleans, offsets, flattening), editable node paths, text layout, units, undo history and the editing operations (`ops`). |
| `vector-render` | CPU renderer on tiny-skia, used for the drawing window, export, printing and thumbnails. Handles gradients, patterns, mesh fills, transparency, merge modes, shadows, contours, extrusions, envelopes, distortions, bitmap effects and lenses. |
| `vector-io` | File formats: `.cdr` (Vector's zip container: drawing JSON, XMP metadata, embedded fonts/ICC profiles, thumbnail; real CorelDRAW files are detected and refused), legacy native `.vct`, SVG import/export, PDF export, PNG/JPEG/BMP/TIFF/WebP raster import/export. |
| `vector-app` | The egui/eframe application (binary `vector.exe`). |
| `xtask` | Build helpers (`cargo run -p xtask -- <command>`): `brand` draws the icon, logo and installer pictures from the brand SVGs; `coverage` writes `docs/COVERAGE.md`; `compare` writes `target/visual/compare.html` (renders next to the reference screenshots, pairs listed in `docs/reference-map.tsv`); `licenses` writes the Legal Notices text; `ui` writes `crates/vector-app/src/ui/data.rs`, the reference interface as data (see below). |

## Application (`crates/vector-app/src`)

- `app.rs`: `VectorApp`, the window layout (menu bar, standard toolbar, property bar, toolbox, palette, dockers, status bar, document tabs, drawing window).
- `commands.rs`: the `Cmd` enum. Every menu item, button and shortcut produces a `Cmd`. `app.run(cmd)` queues it and `exec.rs` executes it. Commands are serializable, so the script recorder can replay them.
- `ui/`: the reference interface as data. `data.rs` (generated by `cargo run -p xtask -- ui` from the
  CorelDRAW 2026 interface definition and the reference's selection-state matrix) lists every menu, right-click
  menu, toolbar, toolbox flyout and property bar item by item, in the reference order, with captions, access keys,
  shortcuts, tooltips, kinds and the selection states that enable each item. `bind.rs` says what Vector does with
  each item (its `Cmd`, and its checked, enabled and caption state). Items without a binding keep the reference
  look and say the feature is not available yet.
- `icons.rs` and `assets/ui/icon-map.tsv`: Vector's own icon drawings (24×24 SVG fragments) and the map from each
  reference icon to the drawing with the same meaning. `xtask ui` reports any reference icon still without one.
- `menus.rs` (menu bar, submenus, right-click menus), `cmdbar.rs` (toolbars and property bars drawn from the data),
  `propbar/` (the property bar fields Vector has: position, size, outline, corners, text, dimensions and the rest),
  `toolbox.rs`, `statusbar.rs`, `palette.rs`, `tabs.rs`, `welcome.rs` (the Welcome Screen): the UI chrome.
- `canvas.rs`: the drawing window. It owns the rulers (drag from a ruler to create guidelines), the cached page render (re-rendered only when the history revision, view or size changes), mouse-wheel zoom and scroll, middle-button pan, the page navigator, the page sorter and full-screen preview.
- `tools/`:
  - `ids.rs`: tool list, flyout groups, names, icons and shortcuts.
  - `interact.rs`: pointer handling for every tool, plus snapping and text-editing keys.
  - `overlay.rs`: on-canvas feedback such as handles, nodes, guides, grid, previews, the caret and snap marks.
  - `shapes.rs`: the Common Shapes library.
  - `mod.rs`: tool state, node operations, corner rounding and text insertion.
- `dialogs/`: modal dialogs. `options.rs` is the Options dialog with every page from the screenshots; `new_doc.rs` is Create a New Document; `forms.rs` holds Export, Print, Trace, Script editor and the others.
- `about.rs`, `sysinfo.rs`: Help ▸ About Vector with System Info and Legal Notices.
- `dockers/`: right-side dockers such as Properties, Objects, Transform, Align and Text.
- `trace.rs`: bitmap-to-vector tracing (k-means colour quantization, region cleanup, contour following, curve fitting).
- `scripting.rs`: macro recording and scripts.
- `ai.rs`: the optional AI Generate feature. It reads the API key from an environment variable.
- `settings.rs`: persisted application settings.

## Data flow

1. Input goes either to `shortcuts::handle` (keys → `Cmd`) or to `canvas::drawing_window` (pointer → `tools::handle_input`).
2. Tools change the document through `DocView::modify(label, |doc, selection| …)`, which records one undo step. Live drags (node editing, envelopes, brushes) record one checkpoint when the drag starts, then update the document directly.
3. The canvas re-renders when `history.revision` changes. The overlay is drawn every frame on top of the cached render.

## Coordinates

- Document units are points (1/72 in), with y pointing down.
- At 100% zoom, one point is 96/72 screen pixels.
- Each object stores its local geometry in the box (0,0)–(w,h) and is placed by its `transform`.

## Tests

```bash
cargo test --workspace
```

The visual tests are GPU snapshot tests: renders of the window, every menu, right-click menu, toolbar, flyout and
property bar, the Welcome Screen pages and an icon sheet, plus a smoke test that drives every tool with simulated
mouse input. They write their images to `target/visual/`; `cargo run -p xtask -- compare` then puts each render
next to its reference screenshot in `target/visual/compare.html`.

```bash
cargo test -p vector-app visual -- --ignored --test-threads=1
```

## Brand assets

The two SVGs in `crates/vector-app/assets/brand/` are the sources:

- `vector-icon.svg` (the airship on its rounded dark tile) is the program icon: `vector.ico` (10 sizes, embedded in
  the exe and used for shortcuts and file types), `icon-256.png` (window icon) and the installer's small picture.
- `vector-logo.svg` (the airship alone) is the logo: `logo.png` (splash screen, About box) and the installer's side
  picture (light and dark, six display scales).

After changing an SVG, run `cargo run -p xtask -- brand`.

## Building the installer

```bash
cargo build --release -p vector-app
"$LOCALAPPDATA/Programs/Inno Setup 6/ISCC.exe" installer/vector.iss
```

The version comes from the workspace `Cargo.toml`, and the installer is written to `dist/Vector-<version>-setup.exe`.
It installs per user without an administrator prompt (or for all users if chosen), adds Vector to "Open with" for
`.cdr` (making it the default for `.cdr` is an unchecked option, because CorelDRAW may own that type), opens `.vct`
files, and keeps the install folder and choices on updates.
